### 2. 서버: 답 받기를 `GameRoom` 잠금 안에서

- 프롬프트: `ANSWER` 핸들러에서 차례 확인·채점·점수·라운드 끝내기를 어디서 할지
- AI 응답: `GameRoom.answer(닉네임, 답)` 하나에서 잠근 채로 「문제가 떠 있나 → 줄 맨 앞인가 → 채점 → 알림 → 정답이면 `finishRound()`」. 따로 하면 같은 순간 문제 시간이 끝날 때 `REVEAL` 뒤에 `RESULT`가 가거나 라운드가 두 번 끝날 수 있음. `AnswerHandler`는 `BuzzHandler`처럼 한 줄로 넘기기만 함
- 판단: 채택. #14 `buzz()`와 같은 이유·같은 모양. 채점기는 #15 `AnswerCheckerSelector`로 유형에 맞게 고르고, 점수는 #12 `ScoreBoard`에 벨 울린 순간의 힌트 수(`BellQueue.hintCountOf`)를 넘김. 라운드 코드(#11)는 고치지 않고 `finishRound()`만 부름

### 3. 메시지 형식

- `ANSWER|4`(4지선다 번호), `ANSWER|피타고라스 정리`(단답형 글). 값이 하나라 글에 `;`가 있어도 그대로
- `RESULT|이건;정답;2`, `RESULT|주성;오답;-1` — 누가;판정;얻은 점수(부호 있는 정수). `시간 초과`는 #21
- 판정 값은 `JoinFailReason`처럼 `common/AnswerResult` 상수로 두고 서버·화면이 같이 씀
- 채팅 알림은 UI 명세서 M7·M8대로 `SYSTEM|이건 님 정답! +2점`, `SYSTEM|주성 님 오답! -1점` (오답 뒤 「○○ 님 차례예요」는 #21)
- 순서: 정답 = `SYSTEM` → `RESULT` → `SCORE` → `REVEAL`, 오답 = `SYSTEM` → `RESULT` → `SCORE`
- 판단: 채택. `MessageType` 주석에 적음. PRD 9절은 따로 고침

### 4. 화면: 답 입력 영역

- AI 응답: `QUESTION`을 받으면 4지선다는 「1. 보기」 버튼 2×2, 단답형은 입력칸을 꺼진 채로 그림. 두 모양은 `MainFrame`처럼 `CardLayout`으로 바꿈. 내 차례(`TURN`)면 켜고 단답형은 커서를 입력칸으로(UI 명세서 2.1 규칙 6), 답을 보내거나 `RESULT`·`REVEAL`을 받으면 끔. 입력칸에 커서가 있었으면 `GameScreen.takeKeyFocus()`로 돌려줘서 스페이스바가 다시 벨이 됨(`ChatPanel`과 같은 방식, 생성자로 `GameScreen`을 받음)
- 판단: 채택. 보기 버튼은 #7 규칙대로 `setFocusable(false)`. 숫자키 1~4는 #14에서 만든 `chooseOption()`에 연결돼 있어서 「4지선다 + 보기 켜짐」일 때만 보내게 채움
- 수정: 처음엔 입력칸을 카드에 바로 넣어 세로로 길게 늘어났음. 가상 화면 캡처로 보고 위쪽 한 줄 + 안내 글로 바꿈
- 정답이면 벨을 끄는 일은 서버가 `RESULT` 바로 뒤에 `REVEAL`을 보내서 기존 `REVEAL` 처리로 꺼짐. 그래서 `BellPanel`은 주석만 고침

### 이해한 내용

- 차례 확인은 화면(버튼 끄기)과 서버(`answer()`의 줄 맨 앞 확인) 두 군데서 한다. 화면만 막으면 콘솔 클라이언트로 `ANSWER`를 직접 보내 우회할 수 있다(N7).
- `GameRoom` 잠금 안에서 `finishRound()`를 다시 불러도 같은 스레드라 멈추지 않는다(`synchronized`는 같은 스레드가 다시 들어갈 수 있다).
