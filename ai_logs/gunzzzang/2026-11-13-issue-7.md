### 1. 영역 나누기와 담당

- 프롬프트: 이슈 #7과 UI 명세서 S4·5절, 뒤에 이어지는 #11·#12·#14·#16·#18·#19·#21·#25를 읽고 게임 화면 틀을 만들어 달라고 요청
- AI 응답: `client/ui/game` 패키지에 영역마다 패널 클래스 6개(라인 A: `QuestionPanel`·`ScorePanel`·`ChatPanel`, 라인 B: `BellPanel`·`QueuePanel`·`AnswerPanel`)와 배치만 하는 `GameScreen`. 각 영역에 `register(MessageRouter)` 자리를 두고, 어떤 메시지를 어느 이슈에서 등록할지 Javadoc 표로 적음
- 판단: 채택. 영역 클래스는 `package-private`이라 `GameScreen` 밖에서는 못 쓴다. 영역끼리 직접 부르는 건 키 입력(`GameScreen` → 벨·채팅·답) 하나뿐이다.

### 2. 배치 방식

- 프롬프트: 수업 예제처럼 `setLayout(null)`로 할지 물음
- AI 응답: UI 명세서 5절이 「창 크기 조절 가능」이라 좌표 고정은 창을 키우면 빈 곳이 생김. 위·가운데·오른쪽·아래로 나누는 단순한 배치라 `BorderLayout` 두 겹 + `GridLayout`(오른쪽 반반)으로 함. CLAUDE.md 3-4 「단순한 영역은 BorderLayout」 범위
- 판단: 채택.

### 3. 키 입력 받는 곳

- 프롬프트: Enter로 채팅 열기·닫기, 닫혀 있을 때만 스페이스바·숫자키가 벨·답이 되게 하려면 어디서 받을지
- AI 응답: `GameScreen`이 `setFocusable(true)` + `KeyAdapter`로 받음(수업 `KeyInputExample`·`FocusExample`). 채팅 입력칸이 열리면 포커스를 가져가니까 스페이스바가 글자로 들어가고, 닫히면 `takeKeyFocus()`로 돌려받음. 따로 「입력칸 열림」 플래그를 검사하지 않아도 됨. 화면이 바뀐 직후 포커스 요청이 실패할 수 있어 `invokeLater`로 미룸(`FocusAdapterExample`)
- 판단: 채택. 실제 동작(`ring`·`openInput`·`chooseOption` 안)은 #14·#16에서 채운다.

### 4. 개발용 화면 전환

- 프롬프트: 서버 없이 게임 화면에 들어가는 임시 버튼 위치
- AI 응답: 타이틀 화면은 #6이 `PlaceholderScreen`을 갈아 끼우므로 거기에 버튼을 두면 충돌. 창 위 메뉴(「개발용」 → 게임 화면 보기 / 타이틀로)로 둠
- 판단: 채택. #11에서 메뉴를 지운다.

### 이해한 내용

- 스페이스바 벨이 되려면 「키를 누른 순간 포커스가 게임 화면에 있어야」 한다. 버튼이 포커스를 가지면 스페이스바가 그 버튼을 누르는 걸로 처리돼서, 영역 안 버튼은 `setFocusable(false)`로 만들어야 한다(#14·#16에서 버튼 만들 때 주의).
- 채팅 입력칸이 열려 있을 때 스페이스바가 벨이 안 되는 건 따로 검사해서가 아니라, 키 이벤트가 포커스를 가진 컴포넌트(입력칸)에만 가기 때문이다.

### 직접 검증한 내용·결과

- 가상 화면(Xvfb)에서 실행: 개발용 메뉴로 게임 화면 전환 → 포커스가 `GameScreen`으로 감. 메서드에 출력문을 넣은 복사본으로 실제 키를 눌러 확인: 스페이스바 → `ring()`, Enter → `openInput()`, 1 → `chooseOption(1)`, 4 → `chooseOption(4)`, 5·A → 무시. 타이틀로 갔다가 돌아와도 스페이스바가 다시 동작
- 오른쪽 숫자 패드: 가상 화면은 NumLock이 꺼져 있어 화살표 키로 들어와 확인 못 함. IntelliJ(Windows)에서 확인
